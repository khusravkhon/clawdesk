# Этап 4: локальная установка и восстановление

Реализован путь восстановления из локального `.tar`/`.tar.enc` через Windows/macOS/Linux лаунчер. Он работает только с установленным личным compose-проектом `clawdesk-local`, каталогом `/var/lib/clawdesk-local` и адресом `127.0.0.1:18080`. Проверочный проект не подставляется в личную карточку. В карточке показаны адрес, compose project, каталог данных, версия OpenClaw запущенного Gateway; недоступная версия обозначена как неизвестная.

Лаунчер проверяет, что адрес принадлежит Gateway выбранного проекта, прежде чем открыть панель. Восстановление требует локальный файл, пароль скачанной копии, предварительную проверку архива и отдельное точное подтверждение `RESTORE clawdesk-local`. Предупреждение перечисляет заменяемые данные и возможность возобновления Telegram/расписаний после запуска. Пароль проходит через stdin, не argv/env Docker и не журнал лаунчера. Проверенный архив копируется в staging лаунчера, а receipt привязан к его выбранному экземпляру; смена файла сбрасывает подтверждение.

## Порядок восстановления

1. Расшифровка штатным `backup-crypto` без вывода содержимого/пароля.
2. Строгий разбор внешнего tar и вложенного gzip/tar: относительные пути, проверки checksum/границ, запрет traversal, дубликатов, symlink/hardlink/devices и неизвестных PAX преобразований.
3. Проверка format/kind/date и точного совпадения версии OpenClaw; допускаются только известные верхние payload-каталоги и три секретных env-ключа.
4. Полное восстановление официальным OpenClaw CLI в приватный staging до остановки выбранного стека. Чтение JSON конфигурации и `PRAGMA integrity_check` SQLite panel/freellmapi. Исходный изменяемый файл после этого не читается при замене данных.
5. Проверка обязательных volumes/mounts. Неизвестная/неполная цель отклоняется вместо частичного восстановления.
6. Остановка выбранного compose-проекта. Sandboxes определяются только по фактическим host mount sources выбранного Gateway/state/shared-files, с точной границей каталога. Общий префикс имени не доказывает принадлежность; чужие контейнеры остаются. Ошибки определения/остановки не позволяют переходить к замене.
7. Копирование кандидатов на целевые файловые системы перед изменением текущих файлов. Предыдущие данные временно перемещаются в `.restore-rollback-*`. При обрабатываемой ошибке изменения откатываются. При неполном откате/неизвестном аварийном завершении стек остаётся остановлен, staging и rollback сохраняются для ручного восстановления. Это не обещание транзакции при выключении питания.
8. Обновление разрешённых ключей `.env`, владельцев файлов и запуск только выбранного compose-проекта. Успешная команда запуска не заменяет пользовательскую проверку внешних подключений.

Тот же риск глобального удаления `openclaw-sbx-*` устранён в factory reset: используются фактические mount roots, неизвестные sandboxes не затрагиваются, ошибка остановки блокирует wipe.

## Изолированная проверка

Docker image: `ghcr.io/khusravkhon/clawdesk-gateway:local`, OpenClaw 2026.8.1. Временный контейнер запускается с `--network none`, только исходники тестов монтируются read-only. Личные volumes, авторизации и Telegram не подключаются.

`deploy/scripts/restore-safe.test.mjs` создаёт фиктивные данные, запускает настоящий `openclaw backup create --verify`, собирает внешний ClawDesk tar, проверяет/распаковывает его, запускает настоящий `openclaw backup restore`, затем читает восстановленные USER.md, расписание, Telegram-конфигурацию (отключённую), fake secrets и содержимое модели fixture. SQLite действительно открывается после восстановления, проверяются запись и integrity_check. Дополнительно кандидат panel SQLite переносится в отдельную временную цель через production `applyPayload`, старые файлы исчезают, новая база читается.

Результат финального прогона: 13/13 тестов; отдельные ownership/ps/inspect/stop-failure проверки: 4/4. Включены ошибки основного rename и отката: прежние данные остаются либо на месте, либо в сохранённом rollback. Незавершённое предыдущее восстановление блокирует повтор и не классифицируется как безопасное для автозапуска. Невалидные пути/links/checksum/дубликаты/несовместимая версия отклоняются. Неоднозначные повторяющиеся ключи целевого экземпляра в `.env` отклоняются; desktop не наследует переменные compose-цели из окружения лаунчера.

Команды из корня проекта:

```powershell
docker run --rm --network none --entrypoint node -e CLAWDESK_RECOVERY_FIXTURE=1 --mount type=bind,source=E:/my_project/clawdesk/deploy/scripts,target=/fixture,readonly ghcr.io/khusravkhon/clawdesk-gateway:local --test /fixture/restore-safe.test.mjs
docker run --rm --network none --entrypoint node --mount type=bind,source=E:/my_project/clawdesk/deploy,target=/fixture,readonly ghcr.io/khusravkhon/clawdesk-gateway:local --test /fixture/clawdesk-recovery-ownership.test.mjs
```

Также прошли desktop `vue-tsc --noEmit`, `cargo check --offline`, bash syntax check (без сборки installer/release).

## Границы доказательства

- Fixture модели доказывает сохранение файла, но не запуск реальной EmbeddingGemma/llama.cpp и не качество поиска.
- npm/.bin symlink fixture штатный SDK не включил в полученный backup. Архив с включёнными symlink/hardlink намеренно отклоняется; такой архив следует проверять/пересоздавать, а не обходить проверку.
- Проверен реальный CLI backup/restore и применение payload к изолированной цели. Полный запуск восстановленного production compose, работа Telegram, OAuth и внешних расписаний в этом тесте не проверены.
- Скрипт отказоустойчив к обрабатываемым ошибкам копирования/rename, но не гарантирует атомарное восстановление нескольких volumes при аварии ОС/Docker. Неполный откат требует ручной проверки сохранённых rollback-каталогов.
- Живые личная/проверочная установки не останавливались и не обновлялись. Commit/push/deploy не выполнялись.
