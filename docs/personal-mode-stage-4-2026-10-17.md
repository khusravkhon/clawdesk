# Этап 4: ежедневное использование личного режима

Реализованы экран «Сегодня», отдельная очередь фиксированных одноразовых напоминаний и восстановление личной установки через лаунчер. Корпоративный режим сохраняет прежний обзор. Изменения находятся в исходниках; установленное приложение и личные Docker-стек/данные не обновлялись. Commit, push и deploy не выполнялись.

## Поведение

- «Сегодня» объединяет ближайшие напоминания, решения владельца, связь, краткие сведения о заметках и здоровье поиска. Независимые источники имеют собственные состояния и время последней успешной проверки. Сбой не превращается в нулевую очередь или ложный успешный статус.
- Новые напоминания отправляют заданный владельцем текст без обращения к модели. Доставка и выполнение — разные состояния. Действия «сделано», «пропустить», «через 30 минут» идемпотентны, сохраняются в SQLite и не меняют старые AI-расписания. Тихие часы действуют только на эту новую очередь.
- После неопределённого результата отправки система показывает unknown и не повторяет сообщение автоматически. Это предотвращение слепых повторов, а не обещание сквозной exactly-once доставки. Подтверждение Telegram означает принятие сообщения провайдером, не прочтение.
- Короткие факты владельца, длинные материалы и проверка поиска разделены ссылками. Повтор синхронизации использует уже сохранённые заметки; автоматического удаления/пересказа памяти нет.
- Лаунчер показывает адрес, compose project, каталог и версию личной установки. Для восстановления нужны проверка архива, receipt выбранной цели и точное подтверждение. Архив полностью готовится до остановки; чужие sandboxes не удаляются по общему префиксу. Неудачный или незавершённый откат оставляет данные для ручного восстановления и не запускает смешанный стек автоматически.
- Интеграционная проверка обнаружила конфликт rollback миграции 0008 с новой 0009. Теперь standalone rollback отказывается работать при применённой более новой миграции до изменения библиотечных таблиц.

Один пропуск общего deploy-прогона — официальный SDK roundtrip: обычный образ Node не содержит OpenClaw. Отдельный прогон в gateway image выполнил его успешно, без пропуска. Проверки восстановления используют только временные фиктивные файлы, SQLite и отключённую Telegram-конфигурацию. Настоящий SDK создал и восстановил архив; тест прочитал заметку, расписание, fake secrets, содержимое fixture модели и проверил SQLite integrity. Это существенно сильнее проверки существования архива.

Команды Linux и подробности безопасного восстановления приведены в [отчёте восстановления](stage-4-recovery-2026-10-17.md). Дополнительные ownership/stop-failure проверки — 4/4; проверка Rust парсинга целевого экземпляра — 1/1.

## Браузерная проверка собранного интерфейса

Изолированный headless Chrome открыл Vite preview собранного Web frontend с фиктивным API. Проверены личная стартовая страница, перенаправление `/today` в company, локальное чтение и действие при `navigator.onLine=false`, один POST при двух быстрых кликах, сохранение подтверждённого действия при завершении устаревшего GET, сохранение предыдущих данных после ошибки fetch, ссылки памяти и отсутствие горизонтального переполнения при ширине 390px. Ошибок JavaScript страницы не было.

Собранный desktop frontend проверен отдельно с фиктивным Tauri invoke: показ выбранной цели, проверка архива перед восстановлением, блокировка неверного подтверждения, очистка пароля и ровно один `restore_local` при двух быстрых кликах. Эта проверка обнаружила и помогла исправить отсутствие синхронного busy guard в обработчиках до первого await. Повторный прогон после исправления и сборки прошёл; настоящий Rust restore этим браузерным сценарием не вызывается.

При смене desktop/mobile breakpoint AppShell перемонтирует страницу. Мобильный снимок сделан после повторного получения данных и появления карточек, а не во время skeleton:

## Границы доказательства

- Это проверка собранного frontend с mock API/Tauri и реальных backend/SQLite/SDK компонентов в изоляции. Полный сценарий установленного desktop-приложения с настоящими данными, обрывом связи и перезапуском ещё не выполнялся.
- Напоминания проверены fake Gateway, включая закрытие и повторное открытие временной SQLite новым экземпляром сервиса. Реальные Telegram-сообщения не отправлялись.
- Восстановление проверяет содержимое fixture модели, но не embeddings inference. Полный destructive `restore.sh` с compose stop/start и восстановление личной установки не запускались.
- Нет гарантии атомарности нескольких volumes при отключении питания. Сохранённый rollback и остановка при неопределённом состоянии требуют отдельной ручной проверки.
- Подключённые боты и старые расписания могут возобновиться после реального восстановления; это явно указано до подтверждения.
