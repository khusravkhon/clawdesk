## Резервная копия и восстановление

Копия установки («Система → Резервные копии», `deploy/scripts/restore.sh`) содержит снимок базы панели и архив `openclaw backup create`. Проверено 05.11.2026 на образе Gateway (`backup create --dry-run`): архив OpenClaw включает всю папку состояния целиком. Значит, вместе с базой панели (отделы, руководители, тимлиды, проекты, правила, задачи, обращения, доступы, обязанности агентов, опрос, противоречия, переносы) в копию попадают:
- папки проектов `company-projects/…` и реестр папок;
- записи сборщика приложений;
- токены и состояние GitHub проектов (`clawdesk/project-github/…`, файлы 0600, как и прочие секреты копии);
- очередь обращений плагина (`clawdesk/requests`);
- рабочие папки агентов с копиями исполнителей, документами команд и копиями Google-документов.

Это подтверждено и настоящим циклом: тест `official OpenClaw backup roundtrip` (`deploy/scripts/restore-safe.test.mjs`) кладёт в состояние папку проекта, токен GitHub проекта, реестр папок, запись очереди обращений и копию документа в рабочей папке, а в базу панели — таблицу отделов. Затем он делает копию настоящим `openclaw backup create --verify`, восстанавливает её `openclaw backup restore` и находит всё на месте; целостность SQLite — `ok`.

После восстановления сообщения, уже доставленные до копии, повторно не отправляются: отметка доставки хранится в базе. Недоставленные к моменту копии будут доставлены — они не уходили ни разу. Восстановление настоящей установки проверено вживую 06.11.2026 (сквозной сценарий, шаг 9): данные на месте, повторов нет; проекты после него не работали — Ж1.

Копия проекта (перенос файлом `.clawdesk-project`, срез 30) и копия установки — разные вещи. Первая переносит один проект на другую установку, вторая возвращает всю установку.

## Инструкция сопровождения

**Обновление.** Локально (PowerShell): `& "C:\Program Files\Git\bin\bash.exe" deploy/scripts/local.sh` — должно закончиться `update healthy`. Перед обновлением панель сама делает копию `before-update`. При неудаче поднимается прежняя версия; самая частая причина — временная сеть до `registry.npmjs.org`, помогает повтор.

**Новая линия OpenClaw.** Обновление ClawDesk оставляет установку на её линии OpenClaw. Новую проверенную линию предлагает «Система → OpenClaw»: копия, сборка, перезапуск, проверка, откат при сбое (срез 39).

**Миграции.** Применяются при старте панели по порядку (`apps/bff/drizzle`, журнал `meta/_journal.json`). Новых шагов отката нет. Вернуться к версии до режима компании можно только восстановлением копии `before-update`: прежняя версия панели новых таблиц не знает.

**Резервные копии и восстановление.** «Система → Резервные копии» — ежедневные (хранятся 7), ручные, перед обновлением и сбросом. Восстановление: `sudo bash deploy/scripts/restore.sh <файл>` (на Docker Desktop — так же, через Git Bash). Оно заменяет всю установку; копии остаются.

**Где лежат данные режима компании.** База панели — всё о структуре, правилах, задачах, обращениях, доступах. В папке состояния OpenClaw лежат:
- `company-projects/` — папки проектов;
- `clawdesk-project-folders.json` — их реестр;
- `clawdesk-build-*.json` — записи сборщика;
- `clawdesk/project-github/` — токены GitHub проектов;
- `clawdesk/requests/` — очередь обращений;
- `workspace/<агент>/` — копии `project/`, `docs/`, `folders/`, `google/`.

**Что проверить после обновления.** «Компания → Возможности установки» (срез 31): всё нужное — «есть». При «плагин обращений — выключено» перезапустите установку: панель включает его раз в минуту при работающем Gateway.

**Известные ограничения.** Перечислены в [матрице возможностей](company-capability-matrix.md) («нет» и «не проверено») и в конце каждого среза журнала. Главные:
- агент без песочницы правилами доступа не ограничен;
- служебные сессии модели копятся в списке сессий главного агента;
- поиск потребностей и правил идёт по словам, а не по смыслу;
- линия OpenClaw 2026.11 ещё не проверена; когда её проверят, владелец поставит её сам из «Системы → OpenClaw» (срез 39). Повторная проверка мастера настройки с несколькими агентами тоже впереди.
