# Приложение ClawDesk в Google

Решение 21.11.2026: общего приложения в проекте нет, ключи в репозиторий не кладём. Каждый владелец установки
подключает Google сам, одним из двух способов:

- **мастер в панели** («Источники данных → Google»): создать своё приложение в Google Cloud и загрузить его файл;
- **ключи в `deploy/.env`** (`CLAWDESK_GOOGLE_CLIENT_ID`, `CLAWDESK_GOOGLE_CLIENT_SECRET`), как ниже: тогда в панели
  сразу «Войти через Google». Так сделано на сервере автора.

Предупреждение Google «приложение не проверено» убирает проверка у Google — её проходит владелец своего приложения.

Данные Google остаются на установке владельца: токены хранит gog в его Gateway, ClawDesk их не видит. Приложение —
только «имя», под которым установка просит доступ.

## Как создать (один раз, ~30 минут)

Лучше от отдельного аккаунта Google для ClawDesk, не личного.

1. [Новый проект](https://console.cloud.google.com/projectcreate) «ClawDesk».
2. Включить API: Gmail, Drive, Docs, Sheets, Calendar (Google Cloud → APIs & Services → Library).
3. [Google Auth Platform → Branding](https://console.cloud.google.com/auth/branding): название «ClawDesk», почта
   поддержки, логотип. Для проверки (ниже) ещё домашняя страница, политика конфиденциальности, условия использования
   и подтверждённый домен.
4. [Audience](https://console.cloud.google.com/auth/audience): External → **Publish app** («In production»).
   В режиме «Testing» Google сбрасывает вход через 7 дней.
5. [Clients → Create client](https://console.cloud.google.com/auth/clients/create): тип **Desktop app**, имя «ClawDesk».
   Секрет такого клиента Google не считает секретным (он лежит у каждого пользователя), поэтому его можно вшить.
6. Client ID и Client secret — в `deploy/docker-compose.yml`, значения по умолчанию у
   `CLAWDESK_GOOGLE_CLIENT_ID` и `CLAWDESK_GOOGLE_CLIENT_SECRET` (или в `.env` установки). После обновления панель
   сама сохранит приложение в gog, если у владельца нет своего.

Владелец со своим приложением Google ничего не теряет: «Использовать своё приложение Google» в мастере.

## Без проверки Google

Работает сразу после шагов выше, но:
- при входе экран «Google hasn’t verified this app» → «Advanced» → «Go to ClawDesk (unsafe)»;
- не больше 100 пользователей за всё время у непроверенного приложения с такими доступами.

Для себя и первых клиентов этого хватает.

## Проверка Google

Проверка не про то, «плохой» ли проект, и открытый код её не заменяет. Google проверяет документы и то, зачем
приложению каждый доступ. Что именно — зависит от доступов:

| Доступ (что просит gog) | Уровень | Что нужно |
|---|---|---|
| Docs, Sheets, Calendar | чувствительный | проверка бренда и доступов: обычно несколько недель, бесплатно |
| Gmail (чтение), Drive (все файлы) | ограниченный | всё то же **плюс** ежегодная проверка безопасности (CASA) у внешней лаборатории, платная |

Что подготовить:
1. **Свой домен** с сайтом ClawDesk, подтверждённый в [Google Search Console](https://search.google.com/search-console).
2. **Домашняя страница**: что делает ClawDesk и зачем ему Google.
3. **Политика конфиденциальности** на том же домене: какие данные Google берутся, где хранятся (на установке
   владельца), что ClawDesk их не получает и не продаёт, и заявление о соблюдении
   [Google API Services User Data Policy, включая Limited Use](https://developers.google.com/terms/api-services-user-data-policy).
4. **Видео на YouTube** (можно «по ссылке»): вход через Google в панели, экран согласия с названием ClawDesk, и как
   агент пользуется каждым доступом (письмо, файл Drive, документ, таблица, событие календаря).
5. **Обоснование каждого доступа** одним-двумя предложениями (в форме проверки).
6. Отправить: Google Auth Platform → Verification center.

Ограниченные доступы. Gmail и все файлы Drive требуют CASA. Перед оплатой спросить у Google в переписке по проверке,
нужна ли она: данные не уходят на сервер ClawDesk, а остаются на сервере самого владельца. Если без Gmail и всех
файлов Drive можно обойтись, проверка остаётся обычной и бесплатной.

## Что не как у Anthropic

Приложение типа «Desktop app» возвращает Google только на `localhost`. Установка на этом компьютере
(`http://127.0.0.1:…`) получает ответ сама — вход в один клик. Установка на сервере с доменом пока просит вставить
адрес, который открылся после входа (шаг в мастере). Чтобы и сервер был в один клик, нужен общий адрес возврата
ClawDesk (свой домен и небольшой сервис), это отдельная задача.
