# Режим компании

Один документ о режиме компании: что он умеет, что осталось сделать, как его сопровождать и на что он опирается в OpenClaw. Обновлено 07.11.2026. OpenClaw 2026.8.35.

Прежние документы удалены 07.11.2026 и есть в истории git (`git show e78ad61:docs/<файл>`):
- два ТЗ: `company-organization-and-interactive-teams.md` и `company-project-creation-and-business-rules.md`;
- приёмка `company-acceptance.md`;
- матрица возможностей `company-capability-matrix.md`;
- журнал работ по срезам `company-implementation-progress.md`;
- список живых проверок `company-live-checks.md` (удалён раньше, `git show a02f9ba:docs/company-live-checks.md`).

## Что умеет

**Структура.** Главный агент, отделы с руководителями, команды с тимлидами: команды GitHub, команды исполнителей проекта и команды без GitHub из шаблонов специалистов. Самостоятельные агенты. Экран «Компания».

**Обращения и задачи.**
- Агент подаёт обращение инструментом `clawdesk_request_up`. Оно идёт по структуре: тимлид → руководитель отдела → главный агент → владелец. На каждом шаге его можно уточнить, ответить, отказать или передать выше.
- Обращения к владельцу приходят в Telegram с кнопками и в тему группы команды. Ответить можно текстом: `/req REQ-… ответ …`. Есть напоминание до срока.
- Задачи компании: очередь у исполнителя, отчёт `clawdesk_task_report`, приёмка владельцем или тимлидом (`clawdesk_task_review`), возврат с замечанием. Задача блокируется, пока ждёт ответа на обращение. Отмена останавливает текущий ход агента.

**Доступы.** Папки, документы команды, Google-документ (для опытных), файлы владельца через «Документы» или через Telegram (`clawdesk_share_file`). Агент получает копию только для чтения в своей рабочей папке. Выдача проверяется по хешу. При отзыве копия и заметки агента о ней удаляются.

**Обязанности агента.** Версии условий: за что отвечает, что запрещено, когда спрашивать. Условия записываются блоком в AGENTS.md, и панель возвращает блок, если его изменили. Расширение условий требует подтверждения. Можно вернуть прежнюю версию. Новая версия сразу сообщается в текущую сессию агента.

**Проекты.**
- Папка проекта внутри `company-projects`. Опрос о проекте с моделью. Бизнес-правила с версиями и поиск противоречий между ними.
- Подбор основы с потребностями из слов владельца. Мастер приложения (шаблон «Доска задач», Node.js). Проверки в изолированном контейнере.
- Задачи по правилу: QA → разработчик → ревьюер → приёмка. Чужие тесты защищены. Проверка нагрузки с условиями и честным выводом.
- План изменений для существующей папки. GitHub проекта: новый репозиторий, PR, импорт, подключение origin. Перенос проекта на другую установку файлом `.clawdesk-project`.

**Наблюдение.** «Активность» — состояние каждого агента. Интерактивный офис с демо-режимом. «Возможности установки» — что есть на этой машине сейчас. Обновление OpenClaw из «Системы».

## Что осталось

**Код:**
- **Удаление команды с группой Telegram.** Сервер отказывает (`telegram_group_linked`), а отдельной отвязки группы нет, поэтому команду GitHub с привязанной группой удалить нельзя. Нужно: у такой команды сначала отвязать группу, потом удалить, как было раньше. Отказ оставить только для команды исполнителей проекта (`apps/bff/src/teams/team-service.ts`, тест в `apps/bff/test/teams.test.ts`).
- **Файл результата для тимлида (по желанию).** Тимлид не видит рабочую папку участника и судит по тексту отчёта. Если нужна сама проверка файла — отдельная задача: копия файла результата тимлиду только для чтения.

**Проверки.** По словам владельца, 07.11.2026 проверены вживую GitHub проекта, Telegram (`/req`, напоминание, тема группы, нажатие кнопки другим участником) и Linux-сервер. Результаты подробно не записаны. Если что-то не совпало, это новая задача в этом списке.

**Не проверено:**
- отдельный ИИ для агента (ключ другого провайдера);
- мастер настройки OpenClaw с несколькими агентами на 2026.8.35;
- линия OpenClaw 2026.11.

## Сопровождение

**Обновление.** Локально (PowerShell): `& "C:\Program Files\Git\bin\bash.exe" deploy/scripts/local.sh`. Должно закончиться `update healthy`. Перед обновлением панель сама делает копию `before-update`. При неудаче поднимается прежняя версия. Чаще всего причина — временная сеть до `registry.npmjs.org`, помогает повтор.

**Новая линия OpenClaw.** Обновление ClawDesk оставляет установку на её линии OpenClaw. Новую проверенную линию предлагает «Система → OpenClaw»: копия, сборка, перезапуск, проверка, откат при сбое. Перед тем как пометить линию проверенной, прогоните контрактный тест `deploy/scripts/contract.sh` (через Git Bash). Должно быть `Contract OK`. Он проверяет и отправку в Telegram вызовами панели.

**Миграции.** Применяются при старте панели по порядку (`apps/bff/drizzle`). Шагов отката нет. Вернуться к версии до режима компании можно только восстановлением копии `before-update`.

**Резервные копии и восстановление.** «Система → Резервные копии»: ежедневные (хранятся 7), ручные, перед обновлением и сбросом. Восстановление: `sudo bash deploy/scripts/restore.sh <файл>` (на Docker Desktop — через Git Bash). Оно заменяет всю установку, копии остаются. Восстановление само ставит метки, и мост заново запоминает папки проектов и агентов. На установке, восстановленной старой версией, метки можно поставить вручную: `docker exec clawdesk-local-gateway-1 sh -c 'touch "$OPENCLAW_STATE_DIR/clawdesk-project-folders.restored" "$OPENCLAW_STATE_DIR/clawdesk/folder-sync.restored"'`.

**Где лежат данные.** База панели хранит структуру, правила, задачи, обращения, доступы, обязанности. В папке состояния OpenClaw:
- `company-projects/` — папки проектов;
- `clawdesk-project-folders.json` — их реестр;
- `clawdesk-build-*.json` — записи сборщика;
- `clawdesk/project-github/` — токены GitHub проектов;
- `clawdesk/requests/` — очередь обращений;
- `clawdesk/folder-sync.json` — синхронизация папок агентов;
- `workspace/<агент>/` — копии `project/`, `docs/`, `folders/`, `google/`, `inbox/`.

**После обновления.** «Компания → Возможности установки»: всё нужное должно быть «есть». При «плагин обращений — выключено» перезапустите установку: панель включает плагин раз в минуту при работающем Gateway.

**Тесты.**
- Сервер: `cd apps/bff; npx vitest run`.
- Интерфейс: `cd apps/web; npx vue-tsc --noEmit -p .`.
- Linux-тесты `deploy/` — в образе Gateway (Git Bash): `MSYS_NO_PATHCONV=1 docker run --rm --network none -v "C:/work/clawdesk/deploy:/d:ro" --user 1000 --workdir /tmp --entrypoint sh ghcr.io/khusravkhon/clawdesk-gateway:local -c 'node --test /d/*.test.mjs /d/scripts/*.test.mjs /d/plugins/*/*.test.mjs'`. Настоящий цикл копии включается так: `-e CLAWDESK_RECOVERY_FIXTURE=1 --workdir /app`.

**Ловушки.**
- `docker stop` Gateway останавливает и панель: у них общая сеть. Зависший Gateway проверяют через `docker pause`; панель замечает его примерно за минуту.
- В PowerShell `bash` запускает WSL. Скрипты из `deploy/` запускайте через Git Bash.

## Известные ограничения

- Агент без песочницы правилами доступа не ограничен.
- Выписки из отозванного документа в истории чата агента остаются, пока сессия не сменится.
- Служебные сессии модели (опрос, противоречия) копятся в списке сессий главного агента.
- Поиск потребностей и правил идёт по словам, а не по смыслу.
- Фото, приложенное в чате панели, OpenClaw не сохраняет файлом, поэтому передать его агенту можно только из Telegram или через «Документы».
- Шаблон приложения один — «Доска задач» на Node.js. Другие основы описаны как направления, но не генерируются.
- При удалении агента его файлы на время уходят в корзину Gateway, которая очищается при каждом старте.

## На что опирается панель в OpenClaw

Раздел из бывшей матрицы возможностей: какие операции OpenClaw, песочницы, Google, Telegram и GitHub используются и как они проверены. Сверяйте его при переходе на новую линию OpenClaw.

Статусы:
- **вживую** — проверено на локальной установке;
- **автотесты** — покрыто тестами с подставным окружением;
- **не проверено** — предположение, которое подтвердит только живая проверка;
- **нет** — не поддерживается.

### Известные ограничения OpenClaw (2026.8.35)

- Патч запуска (`clawdesk-startup-migration-fix`) нужен и в 2026.8.35 и привязан к ней; линия 2026.11 отложена (новое хранение сессий).
- Мастер настройки OpenClaw падает с `AgentSelectionRequiredError` при нескольких агентах: панель останавливает его на шаге каналов. На 2026.8.35 не перепроверено — только вживую.
- Удаление агента в 2026.8.35 не могло перенести файлы из папки состояния вне домашней папки, и Gateway потом не запускался. Исправлено патчем сборки (`patchAgentDeletionSource`); контрактный тест проверяет, что после `agents.delete` не осталось файлов.
