# Этап 3: файловая синхронизация личного режима

Дата: 2026-10-17. Изменения исходников; личные контейнеры, тома и Telegram-боты не изменялись.

## Реализация

`SyncMetadataCache` хранит только результаты чтений текущего процесса: не больше 20 000 записей, не больше пяти минут между полными чтениями каждой записи. Попадания в кэш не продлевают этот срок. Перезапуск создаёт пустой кэш; сохранённые `hashes` остаются лишь базой определения конфликтов, не доказательством неизменности файла.

Ключ содержит корень и относительный путь. Проверка открытого через `O_NOFOLLOW` файлового дескриптора использует bigint `dev`, `ino`, `size`, `mtimeNs`, `ctimeNs`, `mode`, `nlink`. После чтения повторный `fstat` обнаруживает изменение во время чтения. При переносе источник и назначение всегда читаются и хэшируются заново без кэша. Сохраняются fd-обход каталогов, лимиты размера/глубины/числа записей, блокирование ссылок, конфликты и прежняя политика истории.

Изменение inode, метаданных, удаление или блокирование пути инвалидирует запись. Файловые системы с грубой точностью времён и привилегированный внешний писатель не дают абсолютной гарантии только по метаданным; периодическое полное чтение ограничивает это окно пятью минутами. Кэш уменьшает чтение содержимого, но каждый проход всё равно открывает и проверяет файлы/каталоги.

`AgentFolders` получает `metadataCacheEnabled: boolean | (() => boolean)`, по умолчанию false. Getter проверяется перед синхронизацией каждой папки; выключение сбрасывает кэш, повторное включение создаёт новый. Bridge должен включать его только при подтверждённом личном режиме, при ошибке чтения режима — false. Результат содержит `metrics` (`bytesRead`, `bytesHashed`, `cacheHits`, `durationMs`), сохранённые также в status реестра; приватные пути и хэши в метрики не входят.

## Воспроизведение

Docker доступен: `docker info --format '{{.ServerVersion}}'` с escalation вернул `29.8.2`; WSL сообщает Ubuntu и docker-desktop. Отказ sandbox не трактовался как отсутствие Docker. Использован существующий `node:22-alpine`, Node `v22.23.3`, Linux. Сеть отключена, исходники смонтированы только для чтения, тестовые данные находятся исключительно в tmpfs временного контейнера.

```powershell
docker run --rm --network none --read-only --tmpfs /tmp:rw,noexec,nosuid,size=768m --mount 'type=bind,source=E:\my_project\clawdesk\deploy,target=/work,readonly' --workdir /work node:22-alpine node --test clawdesk-agent-folders.test.mjs clawdesk-file-sync.test.mjs

docker run --rm --network none --read-only --tmpfs /tmp:rw,noexec,nosuid,size=768m --mount 'type=bind,source=E:\my_project\clawdesk\deploy,target=/work,readonly' --workdir /work node:22-alpine node clawdesk-file-sync.bench.mjs
```

24 теста прошли, 0 ошибок. Покрыты прежние сценарии обмена и безопасности, тёплый кэш, истечение срока без продления, перевод часов назад, ограничение записей, смена режима, восстановленный mtime при изменившемся ctime, замена inode, ссылки файла/каталога после прогрева, сохранение конфликтов и истории, лимиты одного файла и общего размера на тёплом кэше.

## Фиксированный benchmark

Две изолированные папки по 128 файлов, каждый 65 536 байт (детерминированный Buffer по номеру файла). Прогрев отдельно, затем пять проходов без изменений, одна правка файла и принудительное истечение пяти минут. Сравнивается тот же алгоритм с выключенным и включённым кэшем, без обращения к личным данным.

| Сценарий | Без кэша: чтение / хэширование | С кэшем: чтение / хэширование | Время без / с кэшем |
| --- | ---: | ---: | ---: |
| Пять проходов без изменений | 83 886 080 / 83 886 080 Б | 0 / 0 Б | 893,27 / 309,87 мс |
| Один изменённый файл | 16 908 288 / 16 908 288 Б | 196 608 / 196 608 Б | 145,58 / 59,39 мс |
| Полная периодическая проверка | 16 777 216 / 16 777 216 Б | 16 777 216 / 16 777 216 Б | 153,34 / 151,36 мс |

На неизменных данных 1 280 попаданий, содержимое файлов не читалось и не хэшировалось. Время этого запуска уменьшилось примерно на 65%; время зависит от оборудования и не обещает такой же эффект на пользовательских папках. Правка подтверждена сравнением байтов назначения; полная проверка действительно перечитывает оба дерева.
