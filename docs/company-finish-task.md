## Среда

- Windows 11, Docker Desktop. У владельца терминал PowerShell; `bash` в нём запускает WSL. Скрипты из `deploy/` запускайте через Git Bash: `& "C:\Program Files\Git\bin\bash.exe" deploy/scripts/local.sh`.
- Локальная установка: http://127.0.0.1:18080, проект compose `clawdesk-local`. Контейнеры: `clawdesk-local-gateway-1`, `clawdesk-local-panel-1`. Папка состояния OpenClaw внутри Gateway лежит в `$OPENCLAW_STATE_DIR` (`/var/lib/clawdesk-local/openclaw`). Модули моста лежат в `/usr/local/lib/clawdesk-*.mjs`.
- Если Docker Desktop остановлен после перезагрузки, запустите `C:\Users\user\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe`.
- Обновить установку из текущего кода: `deploy/scripts/local.sh` (через Git Bash). Должно закончиться строкой `update healthy`. Сборка идёт около 10 минут. Если упало на сети до `registry.npmjs.org`, запустите ещё раз.
- В панель входит владелец сам. Пароли и токены не вводите.

### Ловушки, на которых уже теряли время

- `docker stop clawdesk-local-gateway-1` останавливает и панель: у них общая сеть. Чтобы проверить зависший Gateway, используйте `docker pause` и `docker unpause`.
- Поля ввода во Vue не принимают значение, записанное программно. Текст в них нужно печатать.
- Ответ агента приходит через минуты. Ждите события, а не повторяйте запрос: у каждого сообщения есть ключ идемпотентности.
- В тестах папка, созданная заново сразу после удаления, может получить тот же inode. Новую папку создавайте, пока старая ещё существует.
- В Git Bash heredoc портит обратные слэши в JS-строках (`"\n"`). Скрипты правок пишите файлом.

## Правила

1. Работайте в ветке `dev`. Каждую законченную часть (исправление с тестом, обновлённые документы) коммитьте отдельным коммитом с понятным сообщением. **Не пушьте** и не сливайте в `main`.
2. Перед любым внешним или необратимым шагом спросите владельца и дождитесь ответа. Это восстановление копии, сообщения в Telegram, создание репозитория на GitHub, смена модели, мастер настройки OpenClaw.
3. Если проверка не прошла:
   - найдите причину в коде;
   - исправьте и добавьте тест, который без исправления падает;
   - допишите в `docs/company-implementation-progress.md` новый пункт с номером «Ж16», «Ж17» и так далее;
   - добавьте его в таблицу находок в `docs/company-acceptance.md`;
   - закоммитьте.
4. Не трогайте исправления Ж1–Ж15 без причины. Если считаете какое-то неверным, опишите это в отчёте, а не переписывайте молча.
5. Результат каждой проверки записывайте в `docs/company-acceptance.md`: статус «проверено вживую <дата>» или что именно не совпало.

### Находки

**Ж16.** Созданную вручную команду без GitHub нельзя было удалить из панели: «Управление командами» ведёт в список с репозиториями, а у команды на экране «Компания» не было удаления. Теперь этот экран показывает кнопку с подтверждением для вручную созданных команд без репозитория и привязанной группы Telegram. Используется существующая операция удаления. Тест `company.test.ts` проверяет, что панель получает признак доступности для такой команды и не предлагает удаление для команд исполнителей проекта, команд с GitHub или с группой Telegram. До исправления признак отсутствовал, тест падал.

Удаление временной команды подтверждено в панели 07.11.2026 после обновления с результатом `update healthy`. В последующей проверке `teams.test.ts` сервер вернул `409` при попытке удалить команду исполнителей проекта или команду с группой Telegram, сохранив их данные.

**Ж17.** Опрос отвергал корректный ответ `done: true`, если модель возвращала слишком длинный список в сводке. Валидные пункты сводки сокращаются до действующих лимитов показа. Сохранённые ответы и требования при этом не меняются. Тест в `project-interview.test.ts` с 11 исключениями до исправления получил `invalid_reply`, после — `done`.

**Ж18.** В OpenClaw 2026.8.35 удаление агента через Gateway отказывало при переносе файлов состояния из `/var/lib/clawdesk-local/openclaw` в корзину. Журнал удаления оставался незавершённым, при следующем запуске Gateway падал. На установке завершил удаление только тестового агента штатным CLI. В образе добавил привязанное к версии и SHA-256 исправление операции удаления: она учитывает абсолютный каталог состояния, сохраняя проверки идентичности файлов и границы разрешённых путей. Добавлены Linux-тест и проверка результата `agents.delete` в контракте OpenClaw.

**Ж19.** При недоступном Gateway вызов опроса возвращал ошибку, но оставлял активный таймер. Позднее возникала необработанная ошибка тайм-аута. Вызов теперь снимает таймер и подписку при любом исходе. Тест с имитацией недоступного Gateway до исправления находил оставшийся таймер.

У теста Ж6 обнаружен пробел: при малом числе созданий отсутствие `409` само по себе не доказывает, что клиент удалял задачи. `clawdesk-project-load.test.mjs` теперь проверяет пустой список после прогона. На временной копии клиента без `DELETE` эта проверка упала, хотя число созданий было меньше лимита.
