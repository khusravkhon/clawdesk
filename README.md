# ClawDesk

Open-source self-hosted панель для [OpenClaw](https://github.com/openclaw/openclaw): обычный человек без терминала
поднимает главного ИИ-агента, подключает свои сервисы и Telegram, а потом создаёт младших агентов —
диетолога, тренера, YouTube-помощника или команду проекта.

> Статус: MVP в работе. Есть вход в панель по паролю владельца и установка на сервер с HTTPS;
> на настоящем сервере установка ещё не прогонялась.

## Как устроено

```
браузер / десктоп ──HTTP──▶ panel (Fastify BFF + Vue) ──WS loopback──▶ OpenClaw Gateway ──▶ модели, Telegram, сервисы
```

- Браузер говорит только с BFF. BFF — единственный клиент Gateway; device-токен и секреты живут на сервере.
- OpenClaw — зависимость, а не форк. Версия зафиксирована в одном файле: `deploy/openclaw.version`
  (см. «Обновление OpenClaw»).
- Модель — любая: Claude, OpenAI, DeepSeek, Qwen, Kimi, GLM, MiniMax, локальные или подписка. Каждый пользователь
  подключает свой ключ; модель младших агентов выбирается в интерфейсе.

Подробно: [docs/architecture.md](docs/architecture.md).

## Структура

```
apps/
  bff/          Fastify + @openclaw/gateway-client: подключение, парование, RPC-цепочки с откатом, SQLite (Drizzle)
  web/          Vue 3 + Naive UI + Pinia + vue-i18n (ru / en / tg)
packages/
  shared/       zod-схемы и типы, общие для web и bff
  templates/    шаблоны агентов: template.json + SOUL.md / AGENTS.md / USER.md
deploy/
  docker-compose.yml       gateway + panel (+ Caddy для HTTPS, профиль https)
  docker-compose.dev.yml   gateway для разработки на хосте
  install.sh               установка на сервер Ubuntu / Debian: Docker, код, HTTPS, первый запуск
  scripts/init.sh          первый запуск: .env, онбординг OpenClaw, старт
  scripts/local.sh         «Этот компьютер»: тот же стек в Docker Desktop, отдельно от dev
  scripts/update-guard.sh  обновление: бэкап до, проверка после, откат образов при сбое
  scripts/contract.sh      контрактный тест против живого Gateway
  openclaw.version         закреплённая версия OpenClaw (единственный источник)
scripts/
  openclaw-version.mjs     проверка и смена версии OpenClaw во всех копиях, поиск новых релизов
```

## Разработка

Нужно: Node ≥ 22.19 (лучше 24 LTS), pnpm 10, Docker.

```bash
pnpm install
bash deploy/scripts/init.sh --dev        # Gateway в Docker на 127.0.0.1:18789, создаёт apps/bff/.env
pnpm dev:bff                             # BFF на :8787
pnpm dev:web                             # админка на :5173 (проксирует /api на BFF)
```

Проверки: `pnpm typecheck`, `pnpm test`, `pnpm build`, `node scripts/openclaw-version.mjs check`, контрактный тест
`bash deploy/scripts/contract.sh` (то же делает CI на каждый пуш в `dev`).

Релиз: тег `v0.1.0` → GitHub Actions публикует образы `clawdesk-panel`, `clawdesk-gateway`, `clawdesk-sandbox` в ghcr.io.
На сервере `CLAWDESK_VERSION=0.1.0` в `deploy/.env` — установка скачает их вместо сборки (для приватных пакетов
нужен `docker login ghcr.io`, иначе соберёт сама).

## Установка на сервер

Сервер: Ubuntu 22.04 / 24.04 или Debian 12, x86-64, от 2 ГБ памяти (лучше 4 ГБ), 20 ГБ диска, открытые порты 80 и 443.
Домен по желанию: его A-запись должна смотреть на IP сервера. Без домена панель получит адрес `<ip>.sslip.io`.

```bash
# пока репозиторий приватный: скопировать код на сервер (git clone с токеном GitHub или scp), затем
sudo bash clawdesk/deploy/install.sh --domain panel.example.com
```

Установщик ставит Docker, собирает образы, поднимает gateway + panel + Caddy (сертификат Let's Encrypt) и печатает
ссылку `https://<домен>/setup?code=…` — по ней задаётся пароль владельца. Повторный запуск того же
`install.sh` обновляет код и перезапускает, данные (`/var/lib/clawdesk`) и `deploy/.env` сохраняются.

Обновление (повторный `install.sh` или «Обновить» в десктопе) защищено (`deploy/scripts/update-guard.sh`):

1. Перед обновлением работающая версия делает бэкап «Перед обновлением» (виден в «Системе»). Не удался — обновление
   не начинается (`CLAWDESK_UPDATE_SKIP_BACKUP=1` — обновить без него).
2. Текущие образы сохраняются как `clawdesk-rollback/<сервис>:<проект>`, `deploy/.env` — как `.env.before-update`.
3. После старта проверяем, что контейнеры действительно на новых образах (иначе пересоздаём), и ждём до 6 минут
   (`CLAWDESK_UPDATE_HEALTH_TIMEOUT`, секунды): health-check Gateway зелёный и панель подключена к Gateway.
4. Не дождались (или упал любой шаг) — возвращаются прежние образы и `.env`, стек перезапускается, установщик
   завершается с ошибкой. Данные, которые успела записать новая версия, остаются; если прежняя версия на них не
   поднимается, в журнале — команда `restore.sh` для бэкапа из шага 1.

Бэкапы: каждую ночь в `/var/lib/clawdesk/backups` (последние 7), в панели — «Система»: сделать сейчас, скачать
копию (шифруется паролем), сбросить всё. Восстановление: `sudo bash deploy/scripts/restore.sh <файл>`.

При установке, запуске и восстановлении проверяются зависимости ранее одобренных официальных
плагинов. Пропавшие npm-пакеты восстанавливаются в закреплённой версии с проверкой сохранённой
контрольной суммы, без install-скриптов и автоматического разрешения новых возможностей.
Для загрузки отсутствующих зависимостей и локального движка памяти нужен интернет.
В подготовленной копии архива удаляются временные блокировки миграций исходного контейнера;
пользовательские данные и блокировки доставки сообщений сохраняются.

Наружу смотрят только 80/443 (Caddy). Панель — на `127.0.0.1:8080` (доступна через SSH-туннель), Gateway — только
внутри контейнера.

## Обновление OpenClaw

OpenClaw выходит несколько раз в неделю и держит несколько стабильных линий параллельно (патчи 2026.8.x выходят
рядом с 2026.9.x и 2026.10.x). ClawDesk не идёт за `latest` вслепую: каждая новая версия проверяется на живом
Gateway и приходит пулл-реквестом в `dev`.

- **Версия по умолчанию** (её получает новая установка): `deploy/openclaw.version`. Копии, которые не могут читать файл (зависимости
  `@openclaw/gateway-client` / `-protocol` в `apps/bff/package.json`, значение по умолчанию в `docker-compose.yml`,
  `ARG` в `gateway.Dockerfile`, `pnpm-lock.yaml`), сверяет `node scripts/openclaw-version.mjs check` — в CI тоже.
  Плагин llama.cpp и `capabilities` берут версию, которую образ Gateway собран на самом деле.
- **Проверенные версии:** `deploy/openclaw.supported` — всё, что этот код умеет собирать: версия по умолчанию и,
  может быть, более новая линия. Для каждой нужна запись в `FIXES` патча запуска
  (`deploy/clawdesk-startup-migration-fix.mjs`), а CI гоняет контрактный тест на каждой.
- **Установка держит свою линию.** `init.sh` (`deploy/scripts/openclaw-choice.sh`) при обновлении ClawDesk берёт
  новейший проверенный патч той линии, на которой установка работает (по метке образа Gateway
  `org.clawdesk.openclaw-version`, иначе по `deploy/.env`). На другую линию сам не переходит. Если линию убрали
  из кода — переходит на версию по умолчанию, но никогда не на более старую линию. Если установка новее всего, что
  знает код, `init.sh` останавливается, ничего не меняя.
- **Обновление из панели** («Система → OpenClaw»): если среди проверенных есть версия новее работающей, панель
  предлагает её, а владелец решает, обновлять ли. По кнопке мост делает копию «Перед обновлением» (не удалась —
  ничего не меняется) и запускает контейнер-помощник из того же образа (`deploy/clawdesk-openclaw-update.mjs`).
  Помощник собирает образ Gateway для новой версии из файлов сборки, которые несёт сам образ
  (`/usr/local/share/clawdesk/gateway-build`, только разрешённые `gateway.Dockerfile.dockerignore` — без
  `.env`). Затем он пересоздаёт Gateway и контейнеры в его сети (панель, FreeLLMAPI) из их собственной
  конфигурации Docker: пути, тома и порты остаются как были, поэтому это одинаково работает на сервере и в Docker
  Desktop. После этого ждёт проверку здоровья Gateway и подключения панели. При сбое возвращаются прежние
  контейнеры и образ. Ход обновления лежит в `<state>/clawdesk/openclaw-update/status.json` и переживает
  перезапуск панели.
- **Сменить версию по умолчанию:** `node scripts/openclaw-version.mjs set 2026.9.33 && pnpm install`. **Предложить
  новую линию установкам:** `node scripts/openclaw-version.mjs offer 2026.11.2` (версия по умолчанию и клиент
  панели не меняются). Затем запись в `FIXES`, тесты и `OPENCLAW_VERSION=<версия> bash deploy/scripts/contract.sh`.
- **Контрактный тест** (`deploy/scripts/contract.sh`, job `contract` в CI): собирает образы Gateway и панели для
  закреплённой версии, поднимает одноразовую установку (проект `clawdesk-contract`, данные
  `/var/lib/clawdesk-contract`, свой `.env.contract` — рабочие установки не трогаются) и внутри контейнера панели
  гоняет RPC, на которые опирается ClawDesk: подключение и парование, `agents.list/create/update/delete`,
  `agents.files.set/get`, `config.get/patch`, `plugins.list`, `cron.add/list/remove` и ход чата через
  модель-заглушку (`apps/bff/src/contract/smoke.ts`). `OPENCLAW_VERSION=2026.10.4 bash deploy/scripts/contract.sh` —
  проверить другую версию, `CONTRACT_KEEP=1` — оставить стек поднятым.
- **Ежедневный бамп** (`.github/workflows/openclaw-bump.yml`, 05:17 UTC): `npm view openclaw versions`, беты
  пропускаются, учитываются только версии, для которых вышли и клиентские пакеты. На каждую новую версию — ветка
  `openclaw/bump-<версия>` из `dev`, смена версии и lock-файла, сборка, тесты, контрактный тест и PR в `dev` со
  ссылками на релиз, diff и CHANGELOG OpenClaw, таблицей проверок и чек-листом. Метки: `patch` — патч текущей
  линии (`set`); `minor-line` + `manual review` — новая линия (`offer`: её предлагают установкам в панели). Упавшие проверки — PR-черновик с меткой `checks failed`.
  Существующая ветка `openclaw/bump-<версия>` пропускается (удалить ветку — попробовать снова).
- **Ручной запуск:** Actions → OpenClaw bump → Run workflow. По умолчанию dry run: всё то же, но без ветки и PR —
  текст PR в сводке запуска. Поле version — конкретная версия вместо самых новых. Запуск по расписанию и кнопка
  появляются, когда workflow есть в `main`.
- PR от стандартного `GITHUB_TOKEN` не запускает другие workflow, поэтому бамп гоняет проверки сам. С секретом
  `OPENCLAW_BUMP_TOKEN` (токен с правами contents + pull-requests на запись) PR получает и обычный CI.
- Обходы, привязанные к версии, помечены `openclaw-bump-review:`; `node scripts/openclaw-version.mjs review`
  выводит их, и они попадают в чек-лист PR.
- Экран «Система» показывает «ClawDesk 0.1.N · OpenClaw X»: версию релиза панели и версию работающего Gateway.

## Ветки и релизы

- Работа идёт в ветке `dev`: на каждый пуш — сборка, типы, тесты, контрактный тест (`.github/workflows/ci.yml`).
- В `main` попадает только пулл-реквест `dev` → `main`, его сливает владелец на GitHub.
- Каждое слияние в `main` — релиз (`.github/workflows/release.yml`): те же проверки ещё раз, затем установщики
  Windows / Linux (macOS — когда репозиторий станет публичным) в GitHub Releases с версией `0.1.<номер запуска>` (мажор и минор — из
  `apps/desktop/src-tauri/tauri.conf.json`) и `latest.json` для автообновления, и образы сервера в ghcr.io.
- Секреты репозитория: `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (ключ обновлений).

## Десктоп-приложение

`apps/desktop` — Tauri 2 (Windows, macOS, Linux). Само приложение — лаунчер: агенты работают на сервере или в Docker Desktop.

- **Этот компьютер:** ClawDesk в Docker Desktop без сервера — тот же стек, что на сервере (`deploy/scripts/local.sh`:
  проект `clawdesk-local`, данные `/var/lib/clawdesk-local` внутри Docker, панель `127.0.0.1:18080`; dev-стек не трогает).
  Приложение распаковывает вшитый код в свою папку данных и запускает установку через Git Bash; «Обновить» — то же
  самое с кодом новой версии приложения (`deploy/.env` и данные сохраняются). Контейнеры `restart: unless-stopped`
  поднимаются вместе с Docker Desktop; «Открыть панель» сама запускает Docker Desktop, если он выключен.
- **Серверы:** список, вход по SSH-ключу приложения (хранится в Windows Credential Manager / Keychain / Secret Service),
  ключ сервера запоминается при первом подключении и потом сверяется.
- **Установить на сервер:** IP + root-пароль → приложение ставит на сервер свой ключ (пароль не сохраняется),
  заливает по SFTP вшитый в него код этой же версии и запускает `deploy/install.sh` с журналом по шагам.
- **Панель** открывается в отдельном окне: по HTTPS-домену или через SSH-туннель на `127.0.0.1:8080` сервера — домен
  не нужен. Окну панели разрешены только уведомления (одобрения агентов приходят системным уведомлением).
- **Трей** и **автообновление** из релизов GitHub (подпись ключом обновлений).

```bash
pnpm --filter @clawdesk/desktop tauri dev      # нужно: Rust, на Windows — Visual Studio Build Tools (C++)
pnpm --filter @clawdesk/desktop tauri build    # установщики в apps/desktop/src-tauri/target/release/bundle
```

## Шаблоны агентов

Шаблон — папка `packages/templates/agents/<mode>/<id>/` с `template.json` и заготовками `SOUL.md`, `AGENTS.md`,
`USER.md` с `{{плейсхолдерами}}`. Свой шаблон можно прислать пулл-реквестом.

Личный режим: Диетолог, Тренер, Финансы, Бухгалтер (конверты, учёт в `учёт.csv`, куда направить остаток),
YouTube, Соцсети (идеи, тексты, контент-план; идеи для длинных видео — в `для-youtube.md`), Свой агент.

**Мои шаблоны:** любого младшего агента можно изменить в панели («Агенты» → «Изменить»: имя, значок, SOUL.md /
USER.md / AGENTS.md) и сохранить как шаблон — он хранится в базе панели (`user_templates`) и появляется первым в
конструкторе. Имя агента в тексте становится `{{agentName}}`, расписания — пресетами, папка — предложенной папкой.
